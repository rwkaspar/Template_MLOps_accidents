DVC in Version Control Workflow

What is DVC

Data Version Control (DVC) is a tool for tracking and managing versions of data and machine learning models. As mentioned in the previous exercise, DVC was designed to work hand in hand with systems like Git to track versions of large files such as datasets or machine learning models.

In essence, DVC works by replacing large files with much lighter files that point to the original data or models stored elsewhere. By doing this, it is possible to track the lightweight files using a repository on GitHub.

Since DVC was designed to be used with Git, the commands and workflow are similar, allowing you to work with data and model files in the same way as code files. This does not mean that DVC cannot be used alone, but rather that its use is recommended with Git.

It is also possible to work with pipelines that allow creating and reproducing experiments for everyone working on the same project.

DVC is a free, open-source, and platform-agnostic tool, which means it works with a wide range of operating systems, programming languages, and machine learning libraries.

Setup

First, we will start by creating a copy of the Template_MLOps accidents repository (available here) on your personal GitHub account.

To do this, click on the '_Fork_' button at the top right. This will create a copy of all branches; make sure to deselect the option '_Copy the master branch only_'.

Next, we will continue on the virtual machine.

  1. In the current directory of the virtual machine, create a folder called accidents and navigate into it.
mkdir accidents
cd accidents
  1. Clone the GitHub repository that we copied into our account inside the accidents folder. We will clone only the accidents_v2 branch, which differs from the main branch by a few scripts. The --single-branch parameter ensures that the other branches are not cloned. Remember to replace username with your GitHub username.
git clone -b accidents_v2 --single-branch https://github.com/nom_utilisateur/Template_MLOps_accidents.git
  1. Navigate into the Template_MLOps_accidents folder.
cd Template_MLOps_accidents
  1. Create a virtual environment named env, activate it, and install dvc.
virtualenv env
source env/bin/activate
pip install dvc

In our accidents folder, we should have the following structure:

├── Template_MLOps_accidents          
│   ├── .github       
│   ├── env       
│   ├── metrics       
│   ├── models

The next step is to install the necessary libraries for the project and create our dataset.

  1. Start by installing the required libraries using the requirements.txt file.
pip install -r ./requirements.txt
  1. Next, download the data using the import_raw_data script located in the src/data folder.
python ./src/data/import_raw_data.py

You will see the following message in the terminal: 'raw doesn't exist. Do you want to create it. (y/n):'. Simply accept by typing y. Then, you will need to create our dataset from the raw data we just downloaded.

That is, we have just retrieved the raw data that we will use later to consolidate our training set and test set that will be used by our model.

DVC: The First Steps

The important question now is: how do we track this data using DVC? We will answer this question in the following steps, but first, we need to set everything up.

  1. Just like with Git, you need to start by initializing DVC. You will notice that most Git commands have their equivalent in DVC.
dvc init
  You can use the option `dvc config core.analytics false` to prevent information about our usage of the tool from being collected by DVC.

You will notice that two items appeared when we executed the dvc init command: .dvc and .dvcignore. The first is a folder containing DVC configuration information. You generally don't need to open it, but in this course, we will take a look inside to understand what's happening.

The structure of our Template_MLOps_accidents folder now looks like this:

├── Template_MLOps_accidents          
│   ├── .dvc       
│   ├── .github       
│   ├── data       
│   ├── env       
│   ├── metrics       
│   ├── models        
│   ├── notebooks   
│   ├── references       
│   ├── reports       
│   ├── src       
│   ├── .gitignore     
│   ├── .dvcignore       
│   ├── LICENSE       
│   ├── README.md        
│   ├── requirements.txt       
│   └── setup.py

To allow DVC to track data versions, it needs to store this information somewhere, whether locally on your computer or virtual machine, or even in an external folder to your repository. If you open the .dvc folder, you will see that it contains a configuration file called config. This file will specify the information about where our data versions will be stored.

The next step will be to clarify this information. We will demonstrate two ways to do this: one locally on our virtual machine, and another using Google Drive. We will explore the local version in this notebook as well as in the next one. We will then cover the remote version with Google Drive in the fourth notebook.

  1. Let's start with the local version. We will create a new folder in the accidents directory, outside the Template_MLOps_accidents folder. We will name this folder dvc_remote.
mkdir ../dvc_remote

The directory structure of accidents will look like this:

├── dvc_remote       
├── Template_MLOps_accidents

Next, we will set this folder as the location where we will store the versions of our data:

dvc remote add -d remote_storage ../dvc_remote

The -d flag indicates that this will be the default location DVC uses for various backups. The local_remote is the label that DVC will use to identify the location in dvc_remote.

If we open the .dvc/config file, we will now find the following information:

[core]
    remote = remote_storage
['remote "remote_storage"']
    url = ../../dvc_remote

remote indicates the label of the location to be used. In url, you will find the information regarding the path to the location, in this case, locally on our virtual machine.

Now everything is set up to track our data using DVC!

Conclusion

In this notebook, we discussed what DVC is and how to perform the initial steps to set it up for tracking data versions. It is important to note that DVC also allows for tracking versions of models, especially when they become too large to be effectively managed via GitHub.
